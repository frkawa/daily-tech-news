### ★★☆☆☆ [Fragment Refsのずるい使い方](https://zenn.dev/uhyo/articles/react-fragment-refs-hack) `react`

- React 19.3で追加されたFragment RefsはFragmentコンポーネントがrefをサポートし、FragmentInstanceオブジェクトを通じて疑似的な操作が可能になった。
- Activityコンポーネント（React 19.2導入）はDOM要素を描画せず内部要素にdisplay:noneを与える非表示機能を持つが、従来は同様のコンポーネント実装が不可能だった。
- Fragment RefsのobserveUsingやgetClientRectsなどのメソッドを活用することで、独自のHiddenコンポーネント実装が可能になる新しい設計パターンが生まれた。

**Rubyistへの影響:** Rubyistには直接影響なし（React/JavaScript技術の記事）

### ★★☆☆☆ [React Compiler を Babel なしで入れて、useMemo を書くか迷うのをやめた](https://zenn.dev/hacobu/articles/2f58be1f62bcf8) `react` `vite` `tanstacktable` `oxc` `reactcompiler`

- React Compiler をBabel無しで導入可能に。@vitejs/plugin-react 6.1以降、Oxcのoxc-transform-reactを使用できるようになり、Viteのパイプラインをシンプルに保持できる。

- 手動メモ化判断をコンパイラに委譲。useMemo/useCallback/React.memoを原則禁止のlintルール化し、開発者の判断ゆらぎを排除し、コード品質を統一できる。

### ★★★☆☆ [Show HN: Capsule – Single-file web apps that save their data into SQLite](https://withcapsule.app/)

- Capsule は Rust と Tauri 2.0 で構築された HTML アプリと SQLite データベースを単一ファイルに統合するツール。HTML ファイルと関連アセットは直接データベースに埋め込まれる。
- ユーザーデータは localStorage キー・バリューストアまたは MongoDB 風の collections API でドキュメント形式で保存可能。プライバシーとセキュリティを優先し、デフォルトではファイルシステムアクセスやインターネット接続に権限が必要。
- 複数人での編集時に異なるコピーが生成される課題に対し、UUID とタイムスタンプで各データエントリを一意に識別。1.0 版でファイル形式仕様を公開予定。
- データは CSV や JSON で簡単にエクスポート可能。ローカルまたはリモート AI モデルの統合対応で、ドキュメント固有の AI 機能を提供可能。

**Rubyistへの影響:** Ruby コミュニティには直接的な影響は限定的だが、Rust/Tauri での実装参考や Web アプリケーション配布パターンの新しい選択肢として参考になる可能性がある。
